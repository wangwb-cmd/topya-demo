Privacy Policy

Pulse VPN · Review draft · 27 October 2026

Release checklist: the legal entity, privacy mailbox, retention schedule, processing jurisdictions, and exact ad/analytics SDK inventory have not been verified in the materials supplied. Replace this notice with confirmed operator disclosures before publishing.

1. Application and scope

Pulse is an Android VPN product concept. The explanations below follow the documented client flows and identified reporting fields. Production infrastructure, bundled advertising components, and individual release packages have not all been independently examined.

2. Permissions in the connection flow

Starting a tunnel invokes Android's VPN consent interface. Without the system's approval, this app cannot establish its VPN connection. The notification prompt serves a different purpose: it permits Android to show status notifications. Declining it is not a substitute for VPN consent and does not, by itself, prevent a later connection request.

Pulse stores a chosen region so the app can restore a valid selection on this device. Its proposed route controls do not establish that every routing option shown by a mockup is implemented in the Android build. A local selection is not evidence that a server has connected.

3. Guest session and configuration requests

At startup, the documented client obtains a guest session; the visible interface does not ask for email registration. The application also requests service configuration and location data needed to present available routes. This means that “no email login” should not be read as “no service identifier” or “no network requests.”

4. Diagnostic information sent by the app

The documented reporting routines may assemble a device fingerprint and device characteristics alongside guest/user tier, region, the VPN egress IP address, the chosen node, routing details, tunnel establishment or shutdown results, and ad-related diagnostic or interaction events. Submission depends on the app's local-only configuration. The client code queues a native log submission; it does not receive a confirmed server-storage receipt from that call.

The reporting fields reviewed did not include a list of visited websites. This observation is limited to those reporting paths. It does not establish how every component of the VPN network, Android, an advertising partner, or a third-party SDK handles metadata. Pulse therefore makes no universal no-logs certification.

5. Ads and integrated providers

The app's ad flow is coordinated through a TopOn-named orchestrator and includes an AdProfitHub-named event reporter. Server configuration can affect initialization, loading, and display timing. Ads may be skipped and are not promised for each connection. The release build's actual SDK packages and enabled advertising partners were not available for this review. Before release, the operator must name each provider, link its notice, and specify the data it can receive.

6. Storage and user requests

The Pulse design includes on-device diagnostics and a user-initiated report action. The prototype's confirmation text is not sufficient to show that all reporting is opt-in: separate background diagnostics are described in the app reporting path. The operator must explain what a report contains, how cancellation works, and which local files are removed when a user clears data or uninstalls.

Backend retention, deletion periods, access/correction procedures, data-hosting countries, and the identity of the controller are not stated in the reviewed source material. Only the responsible provider can confirm these practices; interface screens do not establish them.
